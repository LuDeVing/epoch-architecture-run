TECHNIQUES:
K0: Squared ReLU in the FFN (Primer): Replace ReLU with ReLU² in the feed-forward block, found by evolutionary search over transformer primitives.
K1: ReLU² in modded-nanoGPT speedrun: ReLU² replaces GELU in a non-gated MLP, bundled with padded embeddings, zero-init projections and QK-norm.
K2: ReLU² vs ReLU vs SwiGLU at matched parameters: Compare ReLU, ReLU², ReGLU and SwiGLU at equal parameter counts, and measure sparsity as well as accuracy.
K3: GLU variants (SwiGLU, GEGLU, ReGLU): A gated MLP multiplies an activated gate projection by a linear value projection.
K4: Layer-wise scaling of FFN width (OpenELM): FFN multiplier and head count grow linearly with depth, so early layers get narrower FFNs and later layers get wider ones.
K5: Layer-wise scaling variants (Crown, Frame, Reverse): Redistribute FFN width and head count across depth using 2-point or 3-point linear interpolation.
K6: Primer depthwise convolution (local mixing): Add a depthwise convolution after the Q, K and V projections to bring in local neighbor information. This sits in attention, not the MLP.
K7: Shift-FFN (adjacent-token differences in the FFN): Add an adjacent-token difference term to the FFN input so the MLP sees local neighbor information. The authors say it works with GLU-style FFNs.
K8: Peri-LN (normalization on sublayer outputs): Apply a norm to the input and also to the output of each sublayer, as in Gemma 2 and OLMo 2. The post-MLP norm divides by the output magnitude, which bounds weight gradients.
K9: Masked Gated Linear Unit (MGLU): Replace the separate gate and value matrices with one shared matrix and learned binary masks, which cuts memory reads.
F0: SwiGLU gave no clear gain in Falcon: Falcon's authors saw no clear zero-shot benefit from SwiGLU at 1B and 3B, so they did not adopt it. They suggested the result depends on hyperparameter tuning.
F1: ReLU² does not beat SwiGLU in accuracy at matched parameters: ReLU² only tied SwiGLU (about 50.5 each). Its advantage is sparsity and efficiency, not lower loss.
F2: OpenELM layer-wise scaling gain is not isolated: OpenELM had no targeted ablation of layer-wise scaling, so its benefit is ambiguous. Follow-up work only found similar losses across variants at small scale.
