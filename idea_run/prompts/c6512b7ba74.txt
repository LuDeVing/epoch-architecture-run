[s024dfab3e9] Readout minus the input token (cancel the similarity prior): The script's skip path carries e_t to the output and the head is E, so the direct path's logits are E Eᵀ e_t: a symmetric form that scores tokens similar to the current one, not ones that follow it. At init the self-token logit is about 7.7 against noise of 0.4, and the near-identity Sinkhorn mixing keeps e_t dominant, so every block must first learn to cancel it; the readout becomes mean(streams) minus λ·e_t with a learned scalar λ starting at 1, so the head reads only what the blocks wrote.
[s1fc45482a3] Frequency-split tying (untie only the frequent rows): The brief says the tied matrix ends up output-shaped because output gradients dominate, and that rare rows (loss 11.6 nats at rank 10k+, which equals the unigram cost) only learn frequency, so they are the rows tying protects. Setting "the two sides conflict most where both gradients are large" as an identity means the conflict lives in the frequent rows; add a zero-initialised 4096 x 384 delta that is added to the logits of ids below 4096 in place (GPT-2 merge order is frequency order), leaving all other rows tied.
[s738c2e48ad] Direction-only tied head with a counted unigram bias: The brief's centering paper identifies output anisotropy, and the rare-token loss equals the unigram cost; literalise "row norm equals log frequency" and the consequence is that the tied table spends its norm, which the input lookup also sees, on a quantity a bias can hold. Logits become g·norm(x)·(E/‖E‖_row)ᵀ + b, with b initialised to log counts from one train shard (stored as a parameter so the exam sees it) and g a learned scalar starting at the baseline row norm.
[sfaf56e6cae] Residual magnitude as confidence temperature: The brief notes residual RMS grows 7.8x through depth and the final RMSNorm sets the softmax temperature to a constant; literalise "RMSNorm equals a temperature of 1/RMS" and the consequence is that per-token magnitude, the sum of how strongly twelve blocks wrote, is a confidence signal thrown away and re-encoded in direction. Scale the normed vector by 1 + α·log(RMS(x_t)/RMS_ref) before the head, α a learned scalar starting at 0.
[s2e00245b7a] History-carrying streams: Four identical input streams carry no more than one, so 3/4 of the input width is redundant; stream k is initialised with e(x_{t-k}) for k=1..3 (padded with the current token at the window start), giving layer 1 a bigram and trigram for free, which the brief says is what weak early layers under tying miss. The final readout becomes a learned softmax over streams initialised on stream 0 so the head does not see a bag of past tokens.
[sf2a3aa32e0] Input-side gradient amplification on the tied table: The open item in the brief: output gradients dominate the tied matrix, so multiply the input-side gradient by g with the value-preserving trick (g·e minus (g-1)·e.detach()). AdamW normalises the summed gradient, so scaling one side changes the update direction rather than its size, which is why it is not a no-op.
[s17f666e1ad] RMSNorm after the embedding lookup: Inkling normalises the embedding directly after lookup; with a tied table the output pressure inflates frequent rows, so the input scale becomes frequency-dependent and the branch writes are dwarfed for frequent tokens. A 384-gain RMSNorm after lookup fixes the input scale to the write scale regardless of row norm.
